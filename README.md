# 新加坡宠物隔离（AQC）空位扫描器

新加坡 AVS 的隔离预约系统 [QMS](https://qms.avs.gov.sg/) 没有空位日历，只能一次输一个到达日期、按 Check Availability 看结果。这个工具用**你自己已登录的会话**替你把这个按钮按几十次，再把结果拼成一张日历：未来 8 个月里哪些日子可以作为入境日、跟上次比新放出了哪些、哪些已经被订走。

- **只读**：代码里写死了只允许按 Check Availability，不会提交、付款、改期或取消。
- **不替你登录**：登录要过图片验证码，只能你自己来。
- 4 个房型扫一轮大约 30 个请求、5~8 分钟，请求之间故意随机停 3~7 秒。**一天扫一两次就够了**，别开着循环刷。

---

## 一次性准备（10 分钟）

1. **QMS 账号**：用你自己的账号，没有就在 [qms.avs.gov.sg](https://qms.avs.gov.sg/) 首页注册。
2. **装 Python 3**（已经装过的跳过）：
   - Windows：去 [python.org/downloads](https://www.python.org/downloads/) 下载安装。**安装程序第一屏底部要勾上「Add python.exe to PATH」**，不勾的话双击扫描会提示找不到 Python。
   - Mac：同一个网址下载 macOS 安装包，一路下一步。
3. **下载这个项目**：GitHub 页面右上绿色 **Code → Download ZIP**，解压到桌面等随便一个地方；会用 git 的直接 `git clone`。
4. 用 **Chrome** 浏览器（下面复制 cookie 的步骤按 Chrome 写的）。

两个依赖包（`requests`、`beautifulsoup4`）第一次双击扫描时会自动安装，不用管。

---

## 第 1 步：改 `config.txt`（只改一次）

用记事本（Mac 用「文本编辑」）打开项目里的 `config.txt`，按你的实际情况改：

| 设置 | 默认值 | 说明 |
|---|---|---|
| `country` | `China` | 宠物出发的国家/地区，填 QMS 下拉里的英文名开头即可。中国大陆就是 `China`（Schedule III，强制 AQC 隔离 30 天），不用改 |
| `cats` | `1` | 猫的数量，没有猫填 `0`（填 0 就不扫猫舍，省时间） |
| `dogs` | `0` | 狗的数量，有狗改成实际只数 |
| `cattery_rooms` / `kennel_rooms` | `1` | 要订几间猫舍 / 狗舍，和 QMS 表单上的 No. of Catteries / Kennels 一个意思 |
| `room_types` | `fan,ac` | 风扇房 `fan`、空调房 `ac`，只想看一种就只写一个 |
| `months_ahead` | `8` | 从明天起往后扫几个月 |

**宠物数量一定要按你实际要订的填。** 系统是按「几只宠物、几间房」查档期的，1 只猫有位不代表 2 只猫也有位。

不是从中国出发的话：先做完第 2 步填好 cookie，再在项目目录里开命令行跑 `python qms_probe.py --countries`（Mac 用 `python3`），会列出 QMS 下拉里的全部国家和代码，挑一行填进去。Schedule I/II 的国家（比如香港、英国）一般不需要订 AQC 隔离房，这个工具对它们没用，程序也会直接提示。

## 第 2 步：填登录态 cookie（每次扫描前都要做）

### 要哪条 cookie、能不能用别人的

登录 QMS 后，浏览器里 `qms.avs.gov.sg` 下面会有好几条 cookie，**真正有用的只有一条**：

| Cookie 名 | 是什么 | 要不要填 | 能用别人的吗 |
|---|---|---|---|
| `ASP.NET_SessionId` | **登录态本身**（服务端会话编号，24 位小写字母和数字） | **必须** | **不能**。必须是你自己登录后拿到的；用别人的等于用别人的账号查，而且别人一登出你就失效 |
| `_sp_id.xxxx` / `_sp_ses.xxxx` | 政府网站访问统计脚本（WOGAA）留下的 | 不用 | 不需要 |
| `_toffsuid` | 网站统计 / 追踪类 | 不用 | 不需要 |

所以：**没有任何一条 cookie 是能拿来复用的，你只需要抄自己的 `ASP.NET_SessionId` 这一条。** 别人分享给你的项目里不会带 `_cookie.txt`（它已经被 `.gitignore` 排除了），你得自己建。

### 操作步骤

1. **第一次用**：把项目里的 `_cookie.example.txt` 复制一份，改名为 `_cookie.txt`。
   （Windows 默认隐藏扩展名，改名时只改成 `_cookie` 即可，别改出 `_cookie.txt.txt`。拿不准的话，直接跳过这步去双击扫描，它找不到文件会自动打开带步骤的教程页。）
2. Chrome 打开 [qms.avs.gov.sg](https://qms.avs.gov.sg/)，登录（账号 + 密码 + 图片验证码），进到 **Reservation → Quarantine Reservation** 页面。
3. 打开开发者工具：Windows 按 `F12`，Mac 按 `⌘ ⌥ I`。顶部切到 **Application**（中文界面叫「应用」）→ 左栏 **Storage → Cookies → https://qms.avs.gov.sg**。
4. 找到 **Name = `ASP.NET_SessionId`** 那一行，双击它的 **Value**，全选复制。
5. 打开 `_cookie.txt`，整个文件只留这一行，存盘：
   ```
   ASP.NET_SessionId=刚复制的那串
   ```
6. **直接关掉 QMS 那个标签页（别点 Logout）**，然后马上去第 3 步。

### 为什么每次都要重新填

QMS 的会话**闲置约 20 分钟就作废**，而且实测是那个开着不动的 QMS 标签页触发的超时。扫描脚本自己发请求反而会给会话续命，所以：

- 复制完就关标签页，立刻扫；
- 点 Logout 会让 `_cookie.txt` 立刻失效，关标签页不会；
- 扫完以后过一阵会话自然过期，下次扫描前再登录、再抄一次（熟练了 30 秒）。

如果 cookie 过期了，双击扫描**不会发任何查询请求**，而是直接在浏览器里打开一页更新教程，照做就行。

> ⚠️ `_cookie.txt` 等于你的 QMS 登录态，**别发给任何人、别传到网上**。

## 第 3 步：双击扫描

- **Windows**：双击 `扫描.bat`
- **Mac**：双击 `扫描.command`。第一次会被系统拦（「无法验证开发者」），在文件上**右键 → 打开 → 打开**，之后就能直接双击。如果双击没反应，打开「终端」，输入 `bash ` （后面有空格），把 `扫描.command` 拖进终端窗口，回车。

黑窗口会一行行显示进度，5~8 分钟后自动在浏览器打开 `report.html`，同时在项目目录存一份 `qms_<时间>.json` 快照。**别删这些快照**：报告里的「较上次」和「放房事件时间表」就是拿它们两两对比算出来的。

## 看懂报告

**各房型摘要**：每个房型最早能约的入境日、最近的一块连续可约区间、和上次扫描相比新增（绿 `+`）和消失（红 `−`）的日期。

**日历**：每个日期格是一个 2×2 小方块，位置固定：

```
 狗·风扇 | 狗·空调
 --------+--------
 猫·风扇 | 猫·空调
```

| 颜色 | 意思 |
|---|---|
| 深绿 | 实查可约 |
| 浅绿 | 推定可约（那个房型往后基本天天有位，后面就不逐日查了，按工作日推定） |
| 灰 | 无位 |
| 橙 | 系统回了看不懂的话，需要你自己去 QMS 上查这一天 |
| 极浅灰 | 没扫（比如你没养狗，狗那两格就一直是这个） |

**口径**：绿色的意思是「**这天可以作为入境日**，从这天起整个隔离期（中国 30 天）的房都订得到」，不是「这天有一张空床」。

**放房事件时间表**：把历史快照两两对比，列出哪段时间里、哪个房型、成块放出或被订走了哪些入境日。扫得越规律，越能看出 AVS 大概什么时候放房。

### 用下来的几条经验（样本不大，仅供参考）

- 远期的位是**成块放出来的**（一次放出一两周的入境日），放出后通常 1~3 天就被订光。所以要抢远期的位，靠的是固定时间多扫几次，看到新块马上去 QMS 下单。
- 近期（大约明天到 8 天后）经常有零星可约日，而且这个窗口每天往后滚一天。这是预约规则造成的，不是有人退订，指望不上。
- 狗舍比猫舍好约得多。以 2026 年 10 月上中旬的 8 轮扫描为例：狗舍从 2027 年 1 月中下旬起基本天天有位；猫舍要到 2027 年 3~4 月，猫空调最紧。但会突然放块：10-13 那轮猫风扇冒出了 2026-11-30 起的一块。

## 常见问题

**双击后窗口提示 `Python not found`**
没装 Python，或者装的时候没勾「Add python.exe to PATH」。重新运行安装程序，选 Modify / 修复，勾上那一项。

**提示 `config.txt has a problem` / 「配置有问题」**
黑窗口上一行会写清楚是第几行、哪里不对（比如设置名拼错了、数字写成了汉字、国家名对不上）。改好再双击。

**扫到一半提示登录态失效 / 网关出错**
已经扫完的房型照样存档、照样出报告，没扫到的房型在报告里会写「本轮没扫到」，**那不等于没有空位**。网关偶尔回 502，程序会自动等 30/60/120 秒重试。

**我改了宠物数量 / 国家之后，「较上次」变成了「首次扫描」**
这是故意的：查的问题变了，跟旧快照比会冒出一堆假的「放出 / 被订走」。之后用同一套设置扫，对比会恢复。

**能不能挂着自动定时扫？**
不行，也不建议。每次都要你本人登录过验证码，而且对政府网站高频请求不礼貌。一天一两次足够。

## 文件说明

| 文件 | 作用 | 要不要动 |
|---|---|---|
| `扫描.bat` / `扫描.command` | Windows / Mac 双击入口 | 不用 |
| `config.txt` | 你的扫描设置 | **第 1 步改一次** |
| `_cookie.example.txt` | cookie 文件模板 | 复制成 `_cookie.txt` |
| `_cookie.txt` | 你的登录态（自己建，不在仓库里） | **每次扫描前更新**，绝不外发 |
| `qms_scan.py` | 扫描主程序：扫完存快照、出报告 | 不用 |
| `qms_probe.py` | 底层：会话、表单回发、结果判定 | 不用 |
| `requirements.txt` | 两个依赖包 | 不用 |
| `qms_*.json` | 每轮快照（自动生成） | 保留 |
| `report.html` | 最新一轮报告（自动生成并打开） | — |
| `cookie_howto.html` | cookie 失效时自动打开的教程页（自动生成） | — |
| `_probe.log` | 运行日志，出问题时看这个 | — |

### 命令行用法（可选）

在项目目录开命令行（Mac 把 `python` 换成 `python3`）：

```bash
python qms_probe.py --check        # 只验 cookie 和 config 对不对，不查日期（1~2 个请求）
python qms_probe.py --countries    # 列出全部出口国和代码
python qms_probe.py --query 15/01/2027 --room cattery_ac   # 只查一个入境日、一个房型
python qms_scan.py                 # 等于双击扫描
python qms_scan.py --report        # 不联网，用已有快照重新生成报告
python qms_scan.py cattery_ac      # 这一轮只扫指定房型
```

## 工作原理（给想改代码的人）

- QMS 是 ASP.NET WebForms 页面。工具直接复刻页面的 AJAX 回发（`X-MicrosoftAjax: Delta=true`），从增量响应里取回新的 `__VIEWSTATE` 接着发下一条，不需要浏览器。
- 登录态只认 `ASP.NET_SessionId`，认证状态存在服务端 session 里。
- 选出口国是一次单独回发，服务端随之回填隔离时长和检疫类别（中国 = 30 天、类别 7），工具直接沿用，不在代码里写死。
- **每次查询前都要把 ViewState 还原到「刚选完国家」的干净状态**：页面一旦进入结果态，再按 Check Availability 拿到的是上一次的旧结果（浏览器手动操作也会这样）。
- 结果有两种：有位时系统一次列出最多 6 个可约日，游标跳到清单最后一天的次日；「No slots are available for the next 30 days」就整段记为无位，游标 +30。所以 8 个月 × 4 个房型只要 30 个左右的请求。
- 某房型在今天 30 天以后、近 21 天里有 ≥10 天可约，就判定后面基本随便约，停止逐日查询，按工作日推定（报告里是浅绿）。
